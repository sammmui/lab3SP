# Синтаксичний аналізатор підмножини мови C

Лабораторна робота 4 
із дисципліни «Системне програмування». Проєкт використовує Flex для лексичного аналізу та Bison для синтаксичного аналізу C-подібної мови.

Після успішного розбору програми проєкт:

- будує абстрактне синтаксичне дерево (AST);
- зберігає AST у файлі `ast.json`;
- виконує AST та виводить результат;
- генерує Python-код у файлі `generated.py`;
- показує AST у браузері за допомогою D3.js.

## Можливості мови

Парсер підтримує:

- типи `int` і `float`;
- оголошення змінних;
- присвоєння;
- арифметичні оператори `+`, `-`, `*`, `/`;
- порівняння `==`, `!=`, `<`, `<=`, `>`, `>=`;
- логічні оператори `&&`, `||`, `!`;
- унарний мінус;
- інструкції `if` та `else`;
- цикл `while`;
- блоки інструкцій `{ ... }`;
- виведення значення через `print(expression);`.

## Структура проєкту

```text
lab_parser/
├── ast.h         # типи вузлів AST та оголошення функцій
├── ast.c         # створення, виконання, серіалізація та генерація AST
├── lexer.l       # правила лексичного аналізу Flex
├── parser.y      # граматика та семантичні дії Bison
├── main.c        # точка входу програми
├── Makefile      # команди для генерації та компіляції
├── test.c        # демонстраційна вхідна програма
└── d3.html       # візуалізація AST у браузері
```

Під час збирання автоматично генеруються:

- `parser.tab.c` і `parser.tab.h` — файли Bison;
- `lex.yy.c` — файл Flex.

## Вимоги

Для збирання проєкту потрібні:

- GCC;
- GNU Make;
- Flex;
- Bison;
- Python 3;
- браузер із доступом до інтернету для завантаження D3.js.

### Встановлення інструментів в Ubuntu або WSL

```bash
sudo apt update
sudo apt install bison flex build-essential
```


## Збирання проєкту

```bash
make clean
make
```

`make` виконує такі кроки:

1. Bison читає `parser.y` і генерує синтаксичний парсер.
2. Flex читає `lexer.l` і генерує лексичний аналізатор.
3. GCC компілює `main.c`, `ast.c` та згенеровані файли в програму `parser`.

## Запуск парсера


```bash
./parser test.c
```

Після успішного розбору програма має:

1. повідомити про успішний синтаксичний аналіз;
2. створити `ast.json`;
3. створити `generated.py`;
4. виконати AST і показати результат у терміналі.

Для демонстраційної програми очікується результат:

```text
120
```

Файл `test.c` використовується як вхідний текст для нашого парсера.

## Запуск згенерованого Python-коду

```bash
python3 generated.py
```

## Перегляд AST у браузері

Сторінка `d3.html` завантажує `ast.json`, тому її потрібно запускати через локальний HTTP-сервер.

```bash
python3 -m http.server 8000
```

```text
http://localhost:8000/d3.html
```
## Як працює проєкт

### Лексичний аналіз

Flex читає вхідний файл і перетворює послідовності символів на токени. Наприклад, вираз:

```c
x = x + 1;
```

перетворюється на токени ідентифікатора, присвоєння, додавання, числа та крапки з комою.

Правила розпізнавання токенів містяться у `lexer.l`.

### Синтаксичний аналіз

Bison отримує токени від Flex і перевіряє їх за граматичними правилами з `parser.y`.

Наприклад, правило оголошення змінної описує конструкції:

```c
int x;
int x = 10;
```

Семантичні дії граматичних правил створюють вузли AST.

### Абстрактне синтаксичне дерево

AST зберігає структуру програми у вигляді дерева. Наприклад, вираз `x + 1` представлений вузлом додавання з двома дочірніми вузлами: змінною `x` і числом `1`.

### Виконання AST

Інтерпретатор обходить AST, зберігає значення оголошених змінних і виконує інструкції. Він підтримує обчислення виразів, умовні інструкції та цикл `while`.

### Генерація Python-коду

Генератор обходить AST і створює відповідну програму мовою Python. Результат зберігається у `generated.py`.

### Візуалізація AST

Проєкт серіалізує дерево у файл `ast.json`. Сторінка `d3.html` завантажує цей файл і показує вузли AST та зв’язки між ними.
